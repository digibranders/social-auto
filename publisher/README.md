# Publisher

Small Vercel project that posts the day's scheduled post to Instagram, so nothing depends on the
Mac being on at posting time. Content (posters and `data/schedule.ts`) is generated by
`scheduler/engine` and arrives here through GitHub.

## Endpoints (both need `Authorization: Bearer $CRON_SECRET`)

| Path | Cron (UTC) | What it does |
|---|---|---|
| `/api/cron` | daily 04:30 (10:00 IST, runs within the hour on the free plan) | Publishes the post that is due (due for 20 hours after its time). Skips it if a post with the same caption is already on the account. `?dryRun=1&post=<id>` prepares a post without publishing. |
| `/api/refresh` | Mondays 05:00 | Renews the Instagram token so it never reaches its 60-day expiry. |

## Alerts

Push alerts go to the ntfy.sh topic in `ALERT_NTFY_TOPIC` (subscribe to it in the ntfy app):

- a post failed to publish
- a client has 7, 3, 1 or 0 scheduled posts left
- token renewal failed, or Instagram issued a different token that must be saved by hand

Alert text never contains tokens or other secrets.

## Environment variables (Vercel, Production)

`CRON_SECRET`, `INSTAGRAM_TOKEN`, `INSTAGRAM_USER_ID`, `PUBLIC_ORIGIN` (public address, so Instagram can
fetch posters), `ALERT_NTFY_TOPIC`.

Replacing a secret: `vercel env update NAME production --sensitive`, then redeploy production,
because running deployments keep the value they were built with.
